## ١. تقييم الواقع الحالي

### ما هو جاهز فعلًا ويستحق البناء عليه

| المكوّن | الحالة |
|---|---|
| بنك الأسئلة | ١٤٩٠ سؤالًا، مراجَعة تحريريًا بالكامل (١٠ دفعات موثّقة في `audit-batch-*.html`) |
| محاكاة قياس | `dist/qiyas.js` — ١٢٠ سؤالًا، ٥ أقسام × ٢٤ سؤالًا × ٢٥ دقيقة، أوزان النوعين لكل مسار، منع الرجوع للقسم المغلق |
| موثوقية الجلسة | `dist/engine.js` — استئناف، حفظ الوقت المرصود/غير المرصود، انتهاء المهلة، حماية التبويبات المتزامنة |
| المصادقة | `scrypt` (N=16384) + salt، `timingSafeEqual`، hash للجلسة في القاعدة، كوكي `HttpOnly; SameSite=Lax; Secure` |
| الاختبارات | ٥ مجموعات، ٦ تأكيدات PASS، تمر كلها بلا تبعيات خارجية |
| النشر | `Dockerfile`، `DEPLOY.md`، صفر تبعيات npm (يعتمد `node:sqlite`) |

هذا أساس أقوى من معظم ما يُسمّى "منصة" في هذا السوق. المشكلة ليست في الجودة، بل في **السقف**.

### العوائق الخمسة الحقيقية أمام التوسع

**١. التقدّم مخزَّن ككتلة JSON واحدة — وهذا يمنع كل شيء تجاري**

```sql
CREATE TABLE progress (
  user_id INTEGER PRIMARY KEY,
  data    TEXT NOT NULL,   -- ← كل تاريخ الطالب في نص واحد
  rev     INTEGER NOT NULL
)
```

الخادم ليس قاعدة بيانات تعليمية، بل **خزانة مزامنة**. لا يوجد صف واحد لكل إجابة. النتيجة المباشرة: لا تقارير للمعلّم، ولا معايرة للأسئلة، ولا محرّك تكيّفي، ولا لوحة مؤسسة، ولا تحليل تسرّب، ولا أي مقياس منتج. أي ميزة تجارية تمرّ من هنا. **هذا هو عنق الزجاجة الأول والوحيد الذي يستحق لقب "حاسم".**

**٢. تصنيف المهارات منهار إحصائيًا**

٦٣١ قيمة `skill` مختلفة على ١٤٩٠ سؤالًا = **٢٫٤ سؤال لكل مهارة**. لا يمكن قياس إتقان مهارة بسؤالين، ولا بناء تشخيص عليها، ولا تخصيص تدريب. التصنيف الحالي وصفٌ تحريري لا أداة قياس.

**٣. توزيع الصعوبة مقلوب، والصعوبة نفسها تخمين**

| | سهل | متوسط | صعب |
|---|---|---|---|
| لفظي | ٤٨٤ | ١٥٦ | ٦٠ |
| كمي | ٤٦٢ | ٢٤١ | ٨٧ |
| **المجموع** | **٩٤٦ (٦٣٪)** | **٣٩٧ (٢٦٪)** | **١٤٧ (٩٪)** |

اختبار قياس يفرّق بين الطلاب في الأعلى، والمنصة أفقر ما تكون هناك. و`difficulty` حقل نصي يدوي — الواجهة نفسها تعترف: «الصعوبة تقدير تحريري يحتاج معايرة بنتائج الطلاب». بلا معايرة تجريبية لا معنى لـ«مستواك» ولا لأي توقّع درجة.

**٤. النصوص مكرّرة بلا كيان مستقل**

٢٥٤ سؤال استيعاب مقروء، والنص مكتوب **داخل** كل سؤال — حتى ٥ نسخ لنفس النص. تعديل نص واحد = ٥ تعديلات. والطالب يرى النص يُعاد من الصفر مع كل سؤال، بينما قياس يعرض نصًا واحدًا وتحته أسئلته.

**٥. الشفرة مكتوبة بأسطر فائقة الطول**

`dist/core.js` = ١٤ سطرًا في ٨ كيلوبايت. `data.js` سطر واحد في ١٤٠٠ كيلوبايت. يعمل، لكنه يجعل المراجعة والعمل الجماعي وتتبّع الأخطاء في git مكلفًا. ولا يوجد `.github/workflows` — **لا تكامل مستمر على الإطلاق**: الاختبارات الخمس الجيدة لا تُشغَّل تلقائيًا على أي تغيير.

### فجوات الأمان المتبقية

| الفجوة | الخطورة | الموضع |
|---|---|---|
| لا تحديد لمعدّل محاولات الدخول | **عالية** — تخمين كلمات المرور بلا سقف | `/api/login` |
| لا تدوير لرمز الجلسة بعد الدخول | متوسطة — تثبيت الجلسة | `startSession` |
| كلمة مرور مؤقتة `randomBytes(6)` | متوسطة — ٤٨ بتًا، وتُسلَّم عبر المدير | `server.js:322` |
| لا تحقّق من البريد | متوسطة — حسابات وهمية، لا استرجاع ذاتي | التسجيل |
| الصلاحيات من `ADMIN_EMAILS` فقط | متوسطة — لا أدوار (معلّم/مشرف/مؤسسة) | `server.js:31` |
| لا سجل تدقيق لأفعال المدير | متوسطة — التصفير والتعطيل بلا أثر | لوحة الإدارة |

## ٢. القرار المعماري الحاسم

**قبل أي ميزة: تحويل `progress` من كتلة إلى أحداث.**

```sql
-- الجدول الذي يفتح كل شيء
CREATE TABLE responses (
  id           INTEGER PRIMARY KEY,
  user_id      INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  item_id      TEXT    NOT NULL,
  session_id   TEXT    NOT NULL,   -- تدريب / تشخيص / محاكاة
  mode         TEXT    NOT NULL,
  chosen       INTEGER,            -- NULL = تُرك فارغًا
  correct      INTEGER NOT NULL,
  ms_spent     INTEGER NOT NULL,
  seq          INTEGER NOT NULL,   -- ترتيب السؤال في الجلسة (لقياس الإجهاد)
  answered_at  TEXT    NOT NULL,
  client_rev   INTEGER NOT NULL    -- للمزامنة وكشف التكرار
);
CREATE INDEX responses_user_time ON responses(user_id, answered_at);
CREATE INDEX responses_item      ON responses(item_id);
```

صفٌّ واحد لكل إجابة. منه تُشتق — بلا أي تغيير آخر — معايرة الأسئلة، وتقارير المعلّم، ونماذج الإتقان، ومقاييس النشاط، والتوصية التكيّفية.

**الاحتفاظ بالمزامنة بالكتلة بالتوازي** في أول مرحلة: الواجهة الحالية تعتمد عليها، و`test-server.cjs` يغطيها (مزامنة جهازين مع كشف التعارض). الكتلة تصبح لقطة مشتقّة، لا مصدر حقيقة. تُسحَب بعد انتقال الواجهة.

**[قرار مطلوب] SQLite أم Postgres؟**
SQLite + `node:sqlite` كافٍ حتى ~٥٠٠٠ مستخدم نشط على خادم واحد، بصفر تبعيات — وهذه ميزة حقيقية. لكن المؤسسات تطلب نسخًا احتياطية حيّة وقراءات متوازية وتعدّد خوادم. توصيتي: **ابقَ على SQLite حتى نهاية المرحلة ٣**، واكتب طبقة الوصول في `server/db.js` بحيث لا تنتشر عبارات SQL في `server.js` — فتصبح الهجرة لاحقًا تغييرًا في ملف واحد لا إعادة كتابة.

## ٣. المراحل

كل مرحلة لها **معيار إنجاز قابل للتحقق**، لا "تم العمل عليها".

### المرحلة ٠ — سياج الأمان (أسبوع واحد)

لا منصة تجارية بلا هذا. وهي أرخص مرحلة في الخطة.

- `.github/workflows/ci.yml`: تشغيل `npm test` على كل push وكل PR، على Node 22 و24
- تحديد معدّل الدخول: ٥ محاولات / ١٥ دقيقة لكل (بريد + IP)، بتأخير تصاعدي
- تدوير رمز الجلسة عند الدخول وعند تغيير كلمة المرور
- `responses` كجدول جديد يُكتب إليه بالتوازي مع الكتلة (ولا يُقرأ منه بعد)
- سجل تدقيق `admin_audit` لكل فعل إداري
- تقسيم الملفات فائقة الطول إلى وحدات مقروءة، مع بقاء الاختبارات خضراء

**معيار الإنجاز:** CI أخضر، و`responses` فيه صفوف حقيقية من استخدام فعلي، وكل اختبارات ما قبل التغيير تمر بلا تعديل في تأكيداتها.

### المرحلة ١ — المحتوى والقياس (٣–٤ أسابيع)

**أ. إصلاح التصنيف** — من ٦٣١ مهارة إلى **٤٠–٥٠ مهارة** هدفها ≥٢٥ سؤالًا لكل مهارة. المهارة الحالية تُحفظ في `skill_note` كوصف تحريري، ويُضاف `skill_id` من التصنيف الجديد. هذا شرط تقني لكل تشخيص لاحق.

**ب. كيان النص المستقل**

```json
"passages": [{ "id": "P-001", "text": "…", "topic": "…", "words": 96 }]
```
والسؤال يشير `passage_id` بدل تكرار النص. مع إصلاح الواجهة لتعرض النص مرة واحدة وتحته أسئلته، كما في الاختبار الحقيقي.

**ج. بناء البنك — الأرقام المطلوبة**

| القسم | الآن | هدف المرحلة ١ | الأولوية |
|---|---|---|---|
| لفظي — صعب | ٦٠ | ٢٥٠ | **الأعلى** |
| لفظي — متوسط | ١٥٦ | ٤٠٠ | عالية |
| كمي — صعب | ٨٧ | ٣٠٠ | **الأعلى** |
| كمي — متوسط | ٢٤١ | ٤٥٠ | عالية |
| المقارنة الكمية | ٤٠ | **[قرار مطلوب]** | تحقَّق أولًا |
| **الإجمالي** | **١٤٩٠** | **٢٥٠٠–٣٠٠٠** | |

**[قرار مطلوب] المقارنة الكمية:** تحقّق من مواصفة قياس **الحالية** قبل استثمار جهد هنا — صيغة الاختبار تغيّرت تاريخيًا وحضور هذا النوع ليس مؤكدًا في النماذج الأخيرة. لا تبنِ ٢٠٠ سؤالًا في نوع قد يكون ملغى.

**د. معايرة تجريبية** — بعد ~٣٠٠ إجابة لكل سؤال من `responses`:
- `p_value` = نسبة الإجابة الصحيحة (الصعوبة الحقيقية)
- `point_biserial` = ارتباط السؤال بالدرجة الكلية (قوة التمييز)
- تحليل المموّهات: خيار لا يختاره أحد = سؤال من ٣ خيارات فعليًا
- **بوابة جودة:** كل سؤال بـ `point_biserial < 0.15` أو `p_value > 0.95` أو `< 0.15` يُعلَّم للمراجعة تلقائيًا

**معيار الإنجاز:** ≥٢٥ سؤالًا لكل `skill_id`، صفر نص مكرر، تقرير معايرة أول يصنّف البنك إلى محتفظ/مراجَع/مسحوب.

### المرحلة ٢ — التعلّم الذكي (٤–٥ أسابيع)

هنا يتحوّل المنتج من "بنك أسئلة" إلى "منصة".

- **تشخيص قصير**: ٣٠–٤٠ سؤالًا تختار العنصر التالي حسب الأداء (تكيّف بسيط قائم على الصعوبة المعايرة، لا IRT كامل بعد) → تقدير أولي لكل مهارة
- **نموذج إتقان لكل مهارة**: بايزي بسيط (معرفة سابقة + تحديث بعد كل إجابة)، يميّز "لم يتدرّب" من "تدرّب وأخفق"
- **الجلسة اليومية المركّبة**: ٦٠٪ مراجعة متباعدة مستحقّة + ٣٠٪ أضعف مهارة + ١٠٪ سؤال أصعب بدرجة من مستواه الحالي
- **التدخّل عند الخطأ**: الشرح موجود في البنك، لكن الشرح وحده لا يعلّم. أضف: سؤالًا موازيًا فوريًا لنفس المهارة بأرقام مختلفة
- **تحليل الوقت**: `ms_spent` يميّز "لا يعرف" (سريع وخاطئ) من "يعرف ولا يُنجز" (بطيء وصحيح) — واستراتيجية العلاج تختلف جذريًا

**مبدأ تعليمي أرفض التهاون فيه:** لا تعرض للطالب "درجة قياس المتوقّعة" رقميًا. البنك غير معاير على عيّنة تمثيلية، وأي رقم سيكون وعدًا لا تستطيع الوفاء به — وهو أسرع طريق لفقدان الثقة ولمشكلة قانونية. اعرض **نطاق إتقان لكل مهارة** و**اتجاه التحسّن**. الواجهة الحالية تلتزم بهذا بالفعل (`learn.js`: «لا تعرض المنصة درجة معيارية أو توقعًا لدرجة قياس») — أبقِ الالتزام.

**معيار الإنجاز:** طالب يكمل التشخيص ثم ٧ جلسات يومية، ويظهر تحسّن قابل للقياس في المهارات المستهدفة مقابل مجموعة ضابطة تتدرّب عشوائيًا.

### المرحلة ٣ — المعلّم والمؤسسة (٤ أسابيع) ← أول إيراد حقيقي

هذه المرحلة هي **نموذج العمل**، لا ميزة إضافية.

- **أدوار حقيقية**: طالب / معلّم / مشرف مؤسسة / مدير نظام (بدل قائمة بريد)
- **مجموعات وروابط انضمام** برمز دعوة
- **لوحة المعلّم**: إتقان المجموعة لكل مهارة، الطلاب المتعثّرون، من توقّف، أكثر الأخطاء شيوعًا
- **واجب مُسنَد** بموعد نهائي وتتبّع إنجاز
- **تصدير** CSV/PDF لتقرير الطالب والمجموعة
- **اختبار موحّد للمجموعة** في نموذج واحد، لمقارنة عادلة

**معيار الإنجاز:** مدرسة واحدة حقيقية بـ ≥٣ معلّمين و≥٦٠ طالبًا تُكمل فصلًا دراسيًا كاملًا على المنصة.

### المرحلة ٤ — التجاري (٣ أسابيع، بالتوازي مع ٣)

- اشتراكات: مجاني محدود / طالب / مؤسسة بالمقعد
- بوابة دفع سعودية: **mada + Apple Pay إلزامي** — بلا mada لا سوق سعودي. (Moyasar / Tap / HyperPay — **[قرار مطلوب]**)
- فاتورة ضريبية متوافقة مع **ZATCA** (فاتورة إلكترونية، ١٥٪ ضريبة) — متطلّب نظامي لا اختياري
- حدود الخطة المجانية: ٣٠ سؤالًا/يوم، محاكاة كاملة واحدة
- لوحة مقاييس: التنشيط، الاحتفاظ بالأسبوع ٤، التحويل، الإيراد المتكرر

### المرحلة ٥ — الوصول والجوّال (مستمر)

- **PWA للعمل دون اتصال** — أولوية مرتفعة في السوق المستهدف، والأساس موجود (التطبيق ثابت أصلًا)
- إمكانية الوصول: قارئ الشاشة، تكبير الخط (موجود)، تباين، لوحة مفاتيح كاملة
- تطبيق أصلي: **[قرار مطلوب]** — PWA جيدة تكفي حتى الطلب الحقيقي؛ لا تبنِ تطبيقين قبل إثبات الاحتفاظ

## ٤. الاستراتيجية التجارية

### السوق

المتقدّمون لاختبار القدرات في السعودية **مئات الآلاف سنويًا**، والقرار الشرائي مدفوع بوالد قلق لا بالطالب — وهذا يغيّر كل شيء في التسويق والتسعير. السوق قائم اليوم على مراكز تدريب حضورية باهظة ومجموعات تلغرام مجانية رديئة. **الفراغ في المنتصف.**

### الشرائح الثلاث، بترتيب الأولوية

| # | الشريحة | يدفع مقابل | الأولوية |
|---|---|---|---|
| ١ | **المدارس ومراكز التدريب** | تقارير المعلّم، إدارة المجموعات، التمييز عن المنافس | **ابدأ هنا** |
| ٢ | **الطالب/الوالد** | محاكاة واقعية، خطة واضحة، تتبّع تحسّن | ثانيًا |
| ٣ | المعلّم المستقل | بنك جاهز + لوحة لطلابه | لاحقًا |

**لماذا B2B أولًا؟** عقد واحد = ٦٠–٣٠٠ مستخدم بتكلفة اكتساب قريبة من الصفر، ودفع سنوي مقدَّم، وتسرّب أقل بكثير، و— الأهم — **تدفّق إجابات كثيف يعاير البنك**. المعايرة هي أصلك الدفاعي الحقيقي: بنك معاير بيانات حقيقية لا يُنسخ، أما ١٥٠٠ سؤال فتُنسخ في أسبوع.

### الخندق التنافسي

الأسئلة ليست خندقًا. الخندق أربعة:

1. **بنك معاير تجريبيًا** — صعوبة حقيقية وتمييز مقاس، لا تخمين
2. **التكيّف المبني على تلك المعايرة** — يتحسّن مع كل طالب
3. **علاقة المؤسسة** — بيانات الفصل داخل المنصة، والانتقال مكلف
4. **الالتزام التحريري الموثّق** — ١٠ دفعات مراجعة منشورة. الشفافية تبيع في سوق مليء بالوعود الزائفة

### المقاييس التي تحكم القرار

| المقياس | الحد المقبول |
|---|---|
| إكمال التشخيص | ≥٧٠٪ |
| العودة في الأسبوع ٢ | ≥٤٠٪ |
| العودة في الأسبوع ٤ | ≥٢٥٪ |
| التحويل من مجاني إلى مدفوع | ≥٥٪ |
| تجديد المؤسسة | ≥٨٠٪ |
| تحسّن مقاس على نموذج ثابت | ≥٨ نقاط مئوية بعد ٦ أسابيع |

الأخير هو المقياس الوحيد الذي يثبت أن المنصة **تعلّم**. البقية تثبت أنها تُستخدم. لا تخلط بينهما.

### المخاطر

| الخطر | الاحتمال | الاستجابة |
|---|---|---|
| **قانوني/حقوق** — مصادر مثل «تسريبات» | **مرتفع** | كل سؤال في البنك يجب أن يكون **مؤلَّفًا أصليًا**. راجع البنك لأي صياغة منقولة حرفيًا، ووثّق أصالة كل سؤال. هذا أخطر بند في الوثيقة. |
| استخدام علامة «قياس» أو «قدرات» بما يوحي باعتماد رسمي | مرتفع | إخلاء مسؤولية صريح في كل صفحة (موجود في الواجهة — أبقِه)، ولا تلميح لاعتماد |
| وعد بدرجة متوقّعة | مرتفع | ممنوع كما في المرحلة ٢ |
| الموسمية الحادة حول موعد الاختبار | مؤكد | عقود مؤسسية سنوية تسوّي التدفّق |
| منافس بتمويل أكبر | متوسط | المعايرة وعلاقة المؤسسة، لا عدد الأسئلة |

## ٥. الترتيب التنفيذي

```
المرحلة ٠  ▓                     أسبوع ١        أمان + CI + جدول responses
المرحلة ١  ░▓▓▓▓                 أسابيع ٢–٥     تصنيف + نصوص + بنك + معايرة
المرحلة ٢  ░░░░▓▓▓▓▓             أسابيع ٥–٩     تشخيص + إتقان + تكيّف
المرحلة ٣  ░░░░░░░▓▓▓▓           أسابيع ٨–١١    أدوار + لوحة معلّم + واجبات
المرحلة ٤  ░░░░░░░░░▓▓▓          أسابيع ١٠–١٢   اشتراكات + mada + ZATCA
المرحلة ٥  ░░░░░░░░░░▓▓▓▓▓▓      أسبوع ١١+      PWA + وصول + جوّال
```

**المسار الحرج:** `responses` → معايرة → تكيّف → لوحة معلّم → بيع مؤسسي. كل حلقة تعتمد على ما قبلها فعليًا، لا تنظيميًا.

**ابدأ غدًا بـ:** جدول `responses` والكتابة إليه، وملف CI. أسبوع واحد، ويفتح كل ما بعده.
