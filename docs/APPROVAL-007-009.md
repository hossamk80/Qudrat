# اعتماد الدفعات السابعة والثامنة والتاسعة ونشرها live

**المُعتمِد:** مدير المنصّة ومالكها (hossam198012@gmail.com) · **التاريخ:** ٢٠٢٦/١٠/٠٧
**المُستند:** `docs/REVIEW-BATCH-007.md` و`REVIEW-BATCH-008.md` و`REVIEW-BATCH-009.md`

الأسئلة مؤلَّفة بالنموذج، فلا تُنشَر إلا بمراجعةٍ بشريّة مسجَّلة. والمراجعات الثلاث
مكتوبةٌ في المستودع، والاعتماد بأمر مالك المنصّة، وهو يُسجَّل في البنك في ثلاثة مواضع:
`items.reviewed_by` و`item_revisions` و`admin_audit`.

## ما جرى التحقّق منه هنا

نُفّذ النشر كاملًا على بنكٍ مُرحَّلٍ من البنك المنشور (١٤٨٩ سؤالًا) للتأكّد من
الأوامر قبل تشغيلها على الخادم:

| | النتيجة |
|---|---|
| الاستيراد | ٣٠٠ مسوّدة · صفر مرفوض · ١٤ نصًّا جديدًا |
| النشر | ٣٠٠ `draft → reviewed` ثم `reviewed → live` في خطوتين مسجَّلتين |
| المُعتمِد | مسجَّل في الأسئلة الثلاث مئة كلّها · صفر سؤال بلا مُعتمِد |
| سجلّ التدقيق | ٣٠٠ `item-status:draft->reviewed` + ٣٠٠ `item-status:reviewed->live` |
| أثر المراجعات | ٦٠٠ قيدًا تَحمل بريد المُعتمِد وملاحظةَ الاعتماد |
| المسوّدات المتبقّية | صفر — ولا يُقدَّم للطلاب إلا الحيّ |
| أرضيّة المهارات | صفر مهارة تحت ٢٥ سؤالًا · أقلّها QG-CIRCLE بـ٣٧ |

## الأوامر على الخادم، بهذا الترتيب

**أولًا — إصلاح سؤال منشور له جوابان صحيحان.** في الدفعة الثانية سؤالُ النسب
«أ : ب = ٣ : ٤ و ب : ج = ٦ : ٥» كان من خياراته «١٨ : ٢٠» و«٩ : ١٠» وهما نسبةٌ
واحدة، فمن أجاب بالأولى أصاب وحُسب عليه خطأ. أصلحتُه، والتعديل يُحمَل على البنك
بأمرين (جُرّبا هنا: سؤالٌ واحد تحدّث و٦٥ بلا تغيير):

```
node server/cli.js sync-items content/batch-002-quant.json --actor hossam198012@gmail.com
node server/cli.js publish-items content/batch-002-quant.json --actor hossam198012@gmail.com
```

**ثانيًا — استيراد الدفعات الثلاث ونشرها:**

```
node server/cli.js import-items content/batch-007-*.json content/batch-008-*.json content/batch-009-*.json

node server/cli.js publish-items content/batch-007-*.json \
  --actor hossam198012@gmail.com --note "اعتماد صاحب المنصّة بعد مراجعة REVIEW-BATCH-007"
node server/cli.js publish-items content/batch-008-*.json \
  --actor hossam198012@gmail.com --note "اعتماد صاحب المنصّة بعد مراجعة REVIEW-BATCH-008"
node server/cli.js publish-items content/batch-009-*.json \
  --actor hossam198012@gmail.com --note "اعتماد صاحب المنصّة بعد مراجعة REVIEW-BATCH-009"
```

الأمر يرفض النشر إن لم يُسمَّ مديرٌ، ويرفض كل سؤالٍ مؤلَّف بالنموذج بلا سجلّ مراجعة،
ويُرجِع الدفعة كلّها إن تعثّر سؤالٌ واحد. وإعادة تشغيله لا تَنشر شيئًا مرّةً ثانية.

## سؤالان لم تَحملهما المزامنة

في الدفعة الأولى «خَزّاف : طين :: حدّاد : ؟» وفي الرابعة «صَيدلية : دواء :: مَشتل : ؟»
أصلحتُهما حين أُضيفت القاعدة الحادية عشرة، لأن المفتاح فيهما يُجاب بتطابق الحروف
(حدّاد ← حديد، مَشتل ← شَتلة). وقد **غيّرتُ جذعيهما** (صارا «نَجّار ← خشب» و«مَنحل ←
عسل»)، و`sync-items` يُطابق بالجذع فيَرفض ما تغيّر جذعه ويقول «استورده بدل تحديثه» —
وهو رفضٌ صحيح: لا يُحدِّث بالتخمين.

والسؤالان المنشوران **ليسا خطأً**، وإنما يَسهل الجواب عنهما بغير فهم العلاقة. فأترك
أمرهما إليك: إبقاؤهما على ما هما عليه لا يَضرّ طالبًا، وإن أردتَ إبدالهما فذلك يَحتاج
طريقَ إحالةٍ إلى `retired` لا يُوجد في الأدوات اليوم، وأبنيه بأمرك.

## حال البنك بعد النشر

٩٠٠ سؤال مؤلَّف أصلًا (الدفعات ١–٩) زيادةً على ١٤٨٩ من البنك المنشور = **٢٣٨٩**،
كلّها `live`، وكلّ مؤلَّفٍ منها يَحمل اسم مُعتمِده.

| | سهل | متوسط | صعب |
|---|---|---|---|
| البنك بعد النشر | ٩٤٦ (٤٠٪) | ٦٣٤ (٢٧٪) | ٨١٠ (٣٤٪) |

وكلّ مهارة من الثلاثين فوق أرضيّة الـ٢٥ سؤالًا. وتسمية «صعب» و«متوسط» تقديرٌ
تحريريّ لا معايرة، ولا تصير معايرةً إلا بعد ٣٠٠ استجابة حقيقية للسؤال الواحد — ولا
يُعرض على طالب تقديرٌ لدرجة قياس بحال.
